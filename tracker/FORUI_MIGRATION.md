## Deviations

- Phase 0: the plan's Phase 8 unused-import removal (`forui` in `new_split_page.dart`) done early so the analyze gate is clean. Prior uncommitted conversion work (bottom nav, cards, buttons across ~14 files) landed in the Phase 0 commit per plan risk note "commit uncommitted conversion work first".
- Phase 1: `FThemeData.toApproximateMaterialTheme()` (forui 0.26) returns `material_ui`'s `ThemeData` — a distinct type from the Flutter SDK `ThemeData` that the SDK `MaterialApp.theme` expects (verified with a minimal probe; forui's own example app roots in `material_ui.MaterialApp`). Switching the app root to `material_ui` was judged out of scope. Instead, `main.dart` adds a `_FThemeMaterialBridge.toSdkMaterialTheme()` extension mapping `FColors` onto the SDK `ColorScheme` (plus scaffold/divider colors), preserving the phase's goal: Material widgets inherit the Forui palette.
- Phase 2: Forui 0.26 typography is `typography.body.<size>` / `typography.display.<size>` (`FTypeface` scales xs3–xl8), not flat `textTheme.bodySmall` — Material `bodySmall` mapped to `typography.body.xs`. `custom_app_bar.dart` has no `Theme.of` reads (already converted); the explicit ghost back-button `leading:` is deferred to Phase 6 per the plan's "once icons migrate".
- Phase 3: API notes — `FTextField` takes text changes via `control: FTextFieldControl.managed(controller:, onChange:)` (no top-level `onChanged`); `error:` is a `Widget?`; `FSelect` uses `items: Map<String, T>` + `FSelectControl<T>.lifted`; multi-select uses `FSelectGroup` + `FSelectGroupItemMixin.checkbox` (no public `FSelectGroupItem` class). The workout_test UI test was repointed to `pumpApp()` + nav-bar `onChange(2)` (Phase 7's pattern, pulled forward: FTextField/FCheckbox require the Forui scope the old bare-`MaterialApp` harness lacked); its `setUp` switched to `InMemoryStorage()` (real `HydratedStorage` deadlocks the fake-async pump, per test_helpers docs) and the `addTearDown(cubit.close)` on the pumpApp cubit was dropped — closing a pumped HydratedCubit hangs the fake-async teardown (app_test never closes either). Material `FilterChip` → `FCheckbox` / `FSelectGroup` checkbox items; warm-up badge `Colors.tertiary` mapped to `colors.secondary`.
- Phase 4: API notes — `showFDialog`'s builder receives `(context, FDialogStyle, Animation)` and the content must be an `FDialog(builder: (context, style))` (title/body rendered manually with `style.titleTextStyle`/`style.bodyTextStyle`, actions as FButton rows); `showFSheet` takes a plain `WidgetBuilder` (no style param), `side: FLayout.btt` for bottom sheets; toasts via `showFToast(title:, duration:)` (FToaster is installed app-wide at the root); `PopupMenuButton` → `FPopoverMenu.tiles(menu: [.group(children: [.tile(...)])], builder: (_, controller, _) => FButton/FIconButton(onPress: controller.toggle))` with `menuAnchor: .topRight, childAnchor: .bottomRight`; `FTile` supports `enabled:` (used for the disabled "Set as primary" menu item). The `_GymTile` trigger kept a Material `IconButton` (tooltip + icon color semantics) instead of the ghost `FButton` — icon-only affordance inside a `ListTile` trailing slot, converted properly in Phase 6 when icons migrate. Dialog/sheet return contracts preserved: `GraphConfig` (graph editor), `bool` (delete/discard confirms), `_WorkoutAction` (end-workout), `Gym` (edit gym), `WorkoutSplitTemplate` (template sheet).
- Phase 5: API notes — `FCard` has no `margin:` (wraps in `Padding`) and its `child` is rendered raw (no default padding); `FItem(title:, subtitle:, prefix:, suffix:, onPress:)` replaces `Card`+`ListTile`+`InkWell` rows; multi-line text blocks use `FItem.raw(child: Row(...))` (title/subtitle truncate single-line); `FItemGroup(divider: .full)` renders sliver-based dividers and is safe inside Columns (standalone wraps a shrinkWrap CustomScrollView). The two `SegmentedButton`s (history list/calendar, exercises browse) became `FTabs` with `FTabEntry(label:, child:)` per-tab content (managed controller keeps which body is built; bodies are shrinkWrap lists inside the outer scroll view) — the plan's risk-note fallback was NOT needed. `ExpansionTile` → `FAccordion` + `FAccordionItem` (available in 0.26); the material `SwitchListTile`s → `FItem` rows with `FSwitch` as `suffix:` (row `onPress` also toggles, mirroring SwitchListTile). The settings Units `DropdownButton` → `FSelect<WeightUnit>.lifted` inside a fixed-width `SizedBox` (FSelect resolves to a Material InputDecorator internally, which cannot have unbounded width inside a Row). Hardcoded colors in `editor_page` (ARGB card fill, `Colors.blueAccent`/`Colors.white` titles) and `session_detail` (`Colors.orange` warm-up chip) replaced with theme tokens (`FCard`, `colors.primary`, `colors.foreground`, `colors.secondary`). The calendar's day-cell `InkWell`s were kept (tap cells, not rows; already Material-themed). Test harnesses updated per the plan's Phase 7 latitude (finder mapping + Forui scope): `settings_test` finders `SwitchListTile` → `FSwitch`, and `settings_test`/`history_test` pump `FTheme(data: FTheme.neutral.light.touch, ...)` around the page (an FTheme is required because FSwitch/FItem's FTappable reads FAccessibilityScope, which only FTheme installs; the full-`pumpApp` shell is unnecessary for these repository-less page pumps — `context.theme` itself falls back to neutral without an FTheme).
